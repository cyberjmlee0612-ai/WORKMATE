# WORKMATE 대시보드 화면 설계서

## 1. 목적과 범위

이 문서는 WORKMATE 대시보드의 정보 구조, 화면 배치, 사용자 동작과 반응형 변화를 정의한다. 서비스 전체 기능과 개발 순서는 [서비스 기획서](planning.md), 공통 시각 규칙은 [디자인 가이드](design-guide.md)를 따른다. 아래 동작은 **구현 목표**이며 현재 코드에 기능이 연결되었다는 뜻이 아니다. 화면의 크기·간격·색상 값은 초기 기준으로 추후 조정할 수 있다.

## 2. 화면 구성: B안

정보량은 Balanced를 기준으로 한다. 주요 정보는 한 화면에서 훑고, 상세 정보는 해당 화면에서 확인하게 한다.

```text
┌──────────────┬────────────────────────────────────────────┐
│ 사이드바     │ 상단 헤더: 인사말 · 알림 · 프로필 · 새 프로젝트 │
│              ├────────────────────────────────────────────┤
│              │ 요약 지표 4개                              │
│              ├────────────────────────────────────────────┤
│              │ 넓은 프로젝트 영역                         │
│              ├────────────────────────────────────────────┤
│              │ 가로형 오늘의 업무 영역                    │
└──────────────┴────────────────────────────────────────────┘
```

읽기 순서는 헤더 → 요약 지표 → 프로젝트 → 오늘의 업무다. 프로젝트와 오늘의 업무를 좌우로 나누지 않고 위아래로 배치한다.

## 3. 사이드바

데스크톱(1024px 이상)에서는 **펼침이 기본**이며 사용자가 버튼으로 접거나 다시 펼칠 수 있다. 태블릿(768–1023px)에서는 사이드바가 자동으로 접히고, 모바일(767px 이하)에서는 사이드바를 숨긴다. 메뉴 순서는 다음과 같다.

1. 대시보드
2. 내 프로젝트
3. 업무 관리
4. AI 업무 도우미
5. 캘린더
6. 리포트
7. 설정

펼친 상태에서는 아이콘과 메뉴명을, 접은 상태에서는 아이콘을 표시하고 툴팁과 접근 가능한 이름으로 메뉴명을 제공한다. 선택된 메뉴는 배경·텍스트·의미상 현재 페이지 표시로 구분한다. 메뉴 클릭 시 해당 화면으로 이동한다. 경로와 각 메뉴의 상세 화면은 별도 설계가 필요하다. 모바일 탐색은 아래 하단 고정 메뉴를 따른다.

### 모바일 하단 탐색

모바일에는 하단 고정 메뉴 5개를 표시한다. 사이드바의 전체 메뉴와 다음처럼 대응한다.

| 하단 메뉴 | 연결 대상 |
| --- | --- |
| 대시보드(홈) | 대시보드 |
| 내 프로젝트(프로젝트) | 내 프로젝트 |
| 업무 관리(업무) | 업무 관리 |
| AI 어시스턴트(AI) | 사이드바의 AI 업무 도우미 |
| 더보기 | 캘린더·리포트·설정 진입 메뉴 |

선택된 메뉴는 Pale Green `#E7F0EA` 배경과 Deep Green `#244C3B` 아이콘으로 구분하고 텍스트·접근성 상태도 함께 제공한다. 더보기의 상세 표시 형태는 후속 확정 사항이다. 고정 메뉴는 콘텐츠와 겹치지 않도록 하단 공간을 확보한다.

## 4. 상단 헤더

왼쪽에는 인사말과 간단한 안내 문구를 둔다. 오른쪽에는 알림, 프로필, **새 프로젝트** 버튼을 배치한다. 좁은 화면에서는 인사말과 동작 영역을 여러 줄로 재배치하되 새 프로젝트 진입은 유지한다.

새 프로젝트 버튼은 프로젝트 생성 창을 연다. 생성 창의 입력 항목, 유효성 검사, 저장 흐름은 별도 설계가 필요하다. 알림과 프로필은 진입 요소로 표시하며 내부 정보와 세부 동작은 미확정이다. 날짜나 사용자 이름을 표시할 경우 실제 데이터와 일치해야 하며 고정 문구를 실시간 정보처럼 보이게 하지 않는다.

## 5. 요약 지표 카드 4개

| 순서 | 지표 | 표시 기준 |
| --- | --- | --- |
| 1 | 전체 프로젝트 | 사용자가 가진 전체 프로젝트 수 |
| 2 | 전체 업무 | 전체 업무 수 |
| 3 | 완료 업무 | 완료 상태인 업무 수 |
| 4 | 전체 진행률 | 완료 업무 수 ÷ 전체 업무 수 × 100 |

전체 업무가 0개이면 전체 진행률은 **0%**로 표시한다. 백분율의 소수점 표시·반올림 방식은 구현 전에 정한다. 각 카드는 지표명, 값, 필요한 경우 짧은 보조 설명을 포함한다. 값의 기준 기간을 임의로 ‘이번 주’ 등으로 표시하지 않는다. 지표의 데이터 범위와 집계 시점은 실제 데이터 모델과 연결할 때 확인한다.

기획서에는 ‘마감 임박 업무’가 대시보드 항목으로 적혀 있다. 이 화면의 네 번째 요약 카드는 사용자 지정에 따라 **전체 진행률**로 설계한다. 마감 임박 업무는 오늘의 업무 목록에서 시각적으로 구분한다. 전체 대시보드에서 마감 임박 업무를 별도 집계로도 보여줄지는 후속 결정 사항이다.

## 6. 프로젝트 영역

요약 카드 아래에 화면의 주된 콘텐츠로 넓게 배치한다. 영역 제목과 프로젝트 목록을 표시한다. 각 프로젝트 카드 또는 행에는 다음 정보를 포함한다.

| 정보 | 표시 방식 |
| --- | --- |
| 프로젝트명 | 가장 먼저 읽히는 제목 |
| 진행률 | 백분율과 진행 막대 등 함께 표시 |
| 완료 업무 수 / 전체 업무 수 | 분자·분모를 명확히 표기 |
| 마감일 | 날짜와 필요한 경우 상태 텍스트 |
| 진행 상태 | 텍스트 레이블과 보조 시각 요소 |

프로젝트 카드를 선택하면 해당 프로젝트 상세 화면으로 이동한다. 카드 안에 다른 동작을 넣을 경우 클릭 영역이 충돌하지 않도록 분리한다. 프로젝트별 진행률도 완료 업무 수 ÷ 전체 업무 수 × 100을 기본 계산 기준으로 제안하며, 해당 프로젝트의 전체 업무가 0개이면 0%로 처리한다. 프로젝트 상태의 종류와 계산 방식, 마감일이 없는 프로젝트의 표시 문구는 후속 확정이 필요하다.

프로젝트가 0개이면 목록 대신 빈 상태 안내와 **프로젝트 추가** 버튼을 표시한다. 버튼은 새 프로젝트 버튼과 동일한 생성 창을 연다. 빈 상태에서는 진행률 막대나 예시 프로젝트를 실제 데이터처럼 표시하지 않는다.

## 7. 오늘의 업무 영역

프로젝트 영역 아래에 가로형 업무 목록을 배치한다. 각 행에는 다음 정보를 표시한다.

| 정보 | 우선순위와 표시 방식 |
| --- | --- |
| 완료 체크박스 | 행의 시작에 배치하고 완료 상태를 조작 |
| 업무명 | 주요 텍스트, 긴 이름은 줄바꿈 |
| 연결된 프로젝트 | 프로젝트명 또는 연결 상태 표시 |
| 우선순위 | 텍스트 레이블과 보조 표시 |
| 마감일 | 날짜를 읽기 쉽게 표기 |
| 완료 여부 | 체크 상태와 완료 텍스트·시각 상태를 일치 |

마감이 임박한 업무는 상태 텍스트와 강조 표시를 함께 사용한다. ‘임박’으로 판단하는 시간 기준은 후속 확정이 필요하다. 완료한 업무의 정렬·노출 유지 방식도 후속 결정 사항이다. 오늘의 업무에 포함되는 기준은 마감일뿐인지, 사용자가 오늘로 계획한 업무도 포함하는지 데이터 모델과 함께 확인해야 한다.

업무가 0개이면 안내 문구와 **업무 추가** 버튼을 표시한다. 업무 추가 버튼이 여는 화면 또는 창과 입력 항목은 별도 설계가 필요하다.

## 8. 주요 사용자 동작

| 요소 | 사용자 동작 | 기대 결과 |
| --- | --- | --- |
| 새 프로젝트 버튼 | 클릭·키보드 활성화 | 프로젝트 생성 창 열기 |
| 프로젝트 카드 | 클릭·키보드 활성화 | 프로젝트 상세 화면으로 이동 |
| 업무 체크박스 | 선택·해제 | 완료 상태 변경 및 표시 갱신 |
| 업무 완료 상태 | 저장된 상태 변경 | 완료 업무 수와 전체·프로젝트 진행률 자동 재계산 |
| 사이드바 버튼 | 클릭·키보드 활성화 | 메뉴 접기·펼치기 |
| 사이드바 메뉴 | 클릭·키보드 활성화 | 해당 화면으로 이동 |
| 프로젝트·업무 빈 상태 버튼 | 클릭·키보드 활성화 | 해당 생성 흐름 시작 |

업무 상태 변경 중에는 중복 입력을 방지하고 결과를 알 수 있어야 한다. 실패 시 상태 복원 및 오류 안내 방식은 구현 단계에서 정한다. 이 표는 동작 요구사항이며 실제 기능 구현을 의미하지 않는다.

## 9. 반응형 배치

| 화면 | 탐색 | 요약 카드 | 본문 |
| --- | --- | --- | --- |
| 데스크톱(1024px 이상) | 펼친 사이드바가 기본, 사용자 접기·펼치기 가능 | 4열 | B안: 넓은 프로젝트 영역 아래 가로형 업무 목록 |
| 태블릿(768–1023px) | 사이드바 자동 접힘 | 2열 | 프로젝트와 업무를 세로 흐름으로 배치하고 정보 줄바꿈 |
| 모바일(767px 이하) | 사이드바 숨김, 하단 고정 메뉴 5개 | 1열 | 모든 주요 영역과 프로젝트 카드·업무 행을 1열로 재구성 |

화면 크기별 콘텐츠 여백과 카드 내부 여백, 카드 간격은 [디자인 가이드](design-guide.md)의 v1.0 기준을 따른다. 모바일에서는 업무명·체크박스를 먼저 보여주고 프로젝트·우선순위·마감일은 다음 줄에 배치할 수 있다. 하단 고정 메뉴가 업무 항목이나 버튼을 가리지 않도록 한다. 어떤 화면에서도 가로 스크롤 때문에 주요 동작이 가려져서는 안 된다.

## 10. 현재 구현과의 차이

현재 `frontend/src/app/page.tsx`에는 사이드바 5개 메뉴, 인사말·새 프로젝트 버튼, 요약 카드 4개, 프로젝트·오늘의 업무 예시가 있다. 프로젝트와 오늘의 업무는 큰 화면에서 좌우 2열이며 값은 고정되어 있다. 사이드바 접기, 알림·프로필, 리포트·설정 메뉴, 프로젝트·업무의 상세 정보, 빈 상태, 실제 이동·완료 동작은 아직 구현되어 있지 않다. 이 문서의 B안 배치와 시각 규칙은 후속 UI 구현 대상이다. 현재 패키지 기준 shadcn/ui 사용은 확인되지 않는다.

## 11. 후속 확정 사항

- 지표의 집계 범위·갱신 시점, 진행률 반올림 방식
- 프로젝트 상태 종류와 마감일 없는 항목의 표시
- ‘오늘의 업무’ 포함 기준, 완료 업무의 정렬·노출 방식, 마감 임박 기준
- 알림·프로필·모바일 더보기 메뉴의 상세 표시 방식과 동작
- 프로젝트·업무 생성 흐름의 입력 항목과 저장·오류 처리
- 확정된 반응형 기준점에서 실제 데이터 길이에 따른 세부 배치

위 항목은 임의로 확정하지 않는다. 문서 작성만으로 기존 화면이나 기능은 변경되지 않는다.
